# BBS Voice · 人声轨道

给 **BBS mod**（Minecraft 1.20.4 / Fabric）加一种新的轨道：**人声轨道**。
输入一句台词，mod 会用 **微软 Edge 的在线语音**把它合成出来，像剪辑软件的 AI 配音一样贴在时间轴上，并且：

* **14 个配音人物**：普通话 6 个（晓晓/晓伊/云希/云健/云扬/云夏）、方言 2 个（东北话/陕西话）、
  粤语 3 个、台湾国语 3 个
* **音量 / 语速 / 音高**可调，且都支持**关键帧曲线**；另有 6 个**情绪预设**（一键往曲线里插关键帧，之后还能拖）
* 支持**自动适配轨道长度**：台词比轨道长时整条加速，避免被截断
* **剪辑会自动长成语音的长度**：合成完成后如果剪辑装不下这句话，自动把剪辑延长到刚好装下（只增不减）
* 支持**自己录音配音**：录一段自己的声音，直接当这条轨道的配音
* 还有起始偏移，以及两种轨道层级（影片级旁白 / 演员级 3D 人声）

> ⚠️ **合成需要联网。** 用的是 Edge 朗读服务（不需要账号、不需要 API key、不需要装 Python），
> 合成结果会缓存成 wav，同一句话只联网合成一次。

## 1. 环境要求

| 组件 | 版本 |
| --- | --- |
| Minecraft | 1.20.4 |
| Fabric Loader | ≥ 0.15.0 |
| Fabric API | 任意 1.20.4 版本 |
| BBS mod | **2.3（1.20.4）** |
| Java | ≥ 17 |
| 网络 | 合成时需要能访问 `speech.platform.bing.com`（国内一般直连可用） |

## 2. 安装

1. 把 Fabric Loader + Fabric API + BBS mod 装好。
2. 把 `bbsvoice-1.0.0-1.20.4.jar` 放进 `mods/`。mp3 解码器（JLayer）已经打进这个 jar 里，不需要额外文件。
3. 启动游戏。

## 3. 使用

安装后会多出**两种**人声轨道：

### 3.1 影片级人声轨道（整部片子的旁白 / 配音）

在**摄影机时间轴**上右键 → `添加剪辑（Add clip）` → **人声配音**。

它和 `bbs:audio`、`bbs:subtitle` 是同一层级，适合旁白、独白、整片统一配音。

### 3.2 演员级人声轨道（每个角色自己的台词）

在**角色编辑器（Replay）的动作轨**里右键 → 添加动作 → **人声配音**。

每个角色一条，默认带 3D 空间音效（按角色位置播放，距离越远越轻），适合多角色对话。

### 3.3 面板说明

| 分组 | 参数 | 说明 |
| --- | --- | --- |
| 配音文本 | 输入框 / **编辑文本** / **重新合成** | 这条轨道要说的话。支持多行，标点会自动变成停顿 |
| 配音人物 | ◀ ▶ 切换 | 14 个 Edge 音色，切换后需要重新合成（音色烘在音频里） |
| 配音来源 | **在线语音（Edge）** / **我的录音** | 切到录音后，下面出现两个图标：麦克风（录制）/ 喇叭（挑一个已有音频文件） |
| 混音 | 音调 | 整体音高（0.25–4.0），**烘进合成**，改了就重新合成 |
| | 音量 | 整体音量（0–4），播放时实时施加，随便拖不触发合成 |
| | 语速 | 整体语速（0.25–4），播放时实时施加 |
| | 偏移 | 从音频的第几秒开始播（正值跳过开头），单位：秒 |
| | 自动适配轨道长度 | 见 3.5 |
| 情绪预设 | 无 / 平静 / 激动 / 悲伤 / 解说 / 悬疑 | 往三条曲线里插关键帧，插完还能手动拖 |
| 自动化曲线 | 音量 / 语速 / 音高曲线 | 打开开关会创建真正的关键帧曲线轨道，**曲线烘进合成** |
| 合成状态 | 状态 / 📂 打开缓存文件夹 / **重新合成** | 见第 4 节 |

**曲线**是真正的 BBS「可动画数值」，打开开关后曲线轨道就被创建，在 **BBS 的关键帧时间轴上**编辑即可
（横轴单位是**影片帧**，相对剪辑起点；纵轴 1.0 表示原值）。
例如想让一句话从很轻渐强到很响：在音量曲线 0 帧放 `0.2`，40 帧放 `1.5` 即可。

### 3.4 用你自己的录音当配音

1. 面板 → **配音来源** → 切到 **我的录音**。
2. 点**麦克风**图标 → 打开 BBS 自带的录音界面（设备选择 / 电平条 / 计时）→ 录完确认。
3. 录音存到 `config/bbs/assets/audio/`，并自动成为这条轨道的配音。也可以点**喇叭**图标直接挑一个已经在音频文件夹里的文件。
4. 录音和合成享受同样的**音量曲线 / 语速曲线 / 自动适配 / 3D 播放**（录音不联网、不合成）。

### 3.5 自动适配轨道长度

面板 → **混音** → **自动适配轨道长度**：开启后，如果配音比轨道长，会整条加速到刚好在轨道内放完
（最长 4 倍速），而不是被硬生生截断。加速靠播放速率实现，所以**音调会一起变高**——和剪辑软件的
"变速不变调"不同，这是实时变速的取舍（想避免音高变化就把语速降到 1.0，用「音调」单独调高音）。

> **剪辑会自动贴合语音长度**：合成完成的那一刻，如果剪辑比这句话短，mod 会把剪辑右边缘延长到刚好装下。
> 规矩是：**只增不减**、**你手动拖过剪辑长度之后就不再自动改**、**开了「自动适配轨道长度」就不自动延长**
> （那种情况由加速负责把语音塞进你定的长度）。如果你主动把剪辑拖短又没开自动适配，状态栏会明确显示
> 「已就绪，剪辑比语音短，会被截断：1.7s > 1.5s」，而不是让你以为没声音是 bug——离开剪辑时 BBS 会停掉
> 剪辑里的声音，所以剪辑太短就是会被切掉。

## 4. 合成与缓存

* **在面板里写这句话的时候**（选中剪辑、改文本、换人物、换配音来源）mod 就在**后台线程**联网合成了，
  不必等播放。播放路径只负责读缓存：如果等到播放头走进剪辑才开始合成，1–3 秒的合成早就错过了这两秒的
  剪辑窗口（第一遍没声音、或者只听到尾巴，就是这么来的）。
* 结果写到 `config/bbs/assets/audio/bbsvoice/<签名>.wav`，之后直接读缓存，不再联网。
* 「签名」由**会改变音频本身的东西**决定：文本 + 配音人物 + 烘进合成的韵律（音调 + 三条曲线）。
  改文本 / 换人物 / 改音调曲线 → 会重新合成；**改音量、语速、偏移、自动适配 → 不会重新合成**，
  因为这几项是播放时实时施加的（所以可以随便打关键帧，不会触发反复合成）。
* **合成失败**（断网、超时、服务拒绝）时，状态栏会直接显示「合成失败：<原因>」，并且**60 秒后会自动重试一次**
  （不是永久拉黑，一次掉包不至于让某句话永远没声音）。也可以随时点「重新合成」立刻重试。
* 「重新合成」按钮会删掉当前签名对应的缓存并重新排队。
* 缓存文件数量上限由设置里的 `缓存数量` 控制，超出会按时间删除最旧的。
* 任务量积累时合成会排队（单线程后台队列），不会卡游戏。一句通常 1–3 秒（冷启动首次 5–10 秒）。

| 选项 | 默认 | 说明 |

## 6. 已知限制（都实测过，请先读这一段）

1. **必须联网**：合成走 Edge 在线服务。断网时状态栏会说清楚是哪种失败（域名解析失败 / 超时 / 服务拒绝），
   并且会重试；已经在缓存里的台词照常播放。合成好的影片**拿到别的机器上播放**，如果没有那份缓存，就需要联网重合成。
2. **服务只给 mp3**：Edge 只支持 mp3 与 webm/opus 两种输出格式（`riff-*-pcm`、`raw-*-pcm`、`ogg-*-opus` 全被拒），
   而 BBS 只能读 wav/vorbis，所以 mod 内置了 mp3 解码器（JLayer），把音频转成 **24 kHz 单声道 16 位 wav**。
   这个格式是固定的，没有采样率选项。
3. **韵律曲线在长句上只有两级**（服务的硬限制，见第 7 节）：一句话被标点切成 ≥3 个分句时，
   曲线会被合并成两段来采样，而不是每个分句一个值。1–2 个分句的句子不受影响。
4. **情绪只能靠韵律曲线**：`mstts:express-as`（cheerful/sad/angry 这些情绪风格）被 Edge 服务拒绝
   （`SSML is invalid`，加上正确的 `xmlns:mstts` 也一样），`<break>` 同样被拒。
   所以「感情」= 语速/音高/音量随时间变化，这也是剪辑软件里调 AI 配音感情的通用做法。
5. **语速 = 变速变调**：整体语速是播放时用播放速率实现的（磁带原理），语速 1.5 倍时音高也会升 1.5 倍。
   曲线里的语速是烘进合成的，不走这条路，所以曲线变速**不会**变调。
6. **相同内容的两次播放会共用同一个音源**：BBS 的 `playUnique` 按资源去重，
   所以「文本+音色+曲线完全相同」的两条轨道同时播放时，实际上只有一个在响（后一条会追赶前一条的位置）。
7. **演员轨道的暂停判定**：影片帧超过 250ms 没有推进就认为暂停并暂停音频；
   极端卡顿（20fps 以下）时可能出现短暂停顿。
8. **未做联机同步**：人声只在客户端本地合成与播放（和 BBS 自身的音频剪辑行为一致），
   服务器上的其他玩家看不到/听不到。
9. **录音用的是 BBS 自带的录音界面**：采集走 BBS 的 OpenAL 录音，能不能录取决于系统里有没有可用录音设备。
   本 mod 只负责把录下来的文件挂到这条轨道上，不做自己的采集实现；真录不了时可以先在别处录好，
   再用**喇叭**按钮从音频文件夹里挑文件。
10. **自动适配上限 4 倍速**：再长也不继续加速了（宁可截断，也不让声音变成鸭子叫）。
11. **曲线在 BBS 的关键帧时间轴上编辑**：打开开关只是创建曲线轨道，关键帧本身用 BBS 自己的编辑器打。
12. **要等游戏的音频引擎就绪才会出声**：OpenAL 是 Minecraft 自己初始化的。在它就绪之前直接碰 OpenAL
    不只是失败一次——LWJGL 的能力类会初始化失败并**永久坏掉**，连游戏自带的音效一起完蛋。
    所以本 mod 会先安全地探测 AL 能力是否就位（不触发那个坏掉的初始化），没就位就安静等待、
    不播也不崩。副作用：刚进标题界面那几秒（音频引擎常常还在启动）可能还没声音，之后就正常。
13. **BBS 读 wav 时会往日志里打一条 `java.io.EOFException` 堆栈**：那是 BBS 自己的 wav 读取器
    把"chunk 读完"当成 EOF 并顺手 `printStackTrace()`，音频本身加载成功（时长、播放都正常），
    属于 BBS 侧的日志噪音。
14. **配音人物是一个固定名单**：可以从服务的 `voices/list` 拿到更多音色（英文、日语、韩语…），
    但这一版只挑了中文相关的 14 个。旧的影片存档如果存的是老引擎的人物 id，会自动回退到「晓晓」。
15. **刚打完字就立刻播放，第一遍可能还是没声音**：合成要联网（一句 1–3 秒，冷启动更久）。面板一打开
    就会预热，所以正常"选中剪辑 → 写字 → 播放"的流程不会碰上；真赶上了，等状态栏变成「已就绪」再播一次即可。
16. **剪辑长度是自动写的**：合成完成时 mod 会改剪辑的 `duration`（这就是"贴合语音"）。它不是用户操作，
    所以不走 BBS 的撤销栈；想改回去直接拖剪辑右边缘就行。

## 7. 工作原理

```
文本 ──▶ ProsodyPlanner ──▶ List<ProsodySpan> ──▶ SsmlBuilder ──▶ SSML
         按标点切分句（≥3 句时合并成 2 组）      每条带 rate/pitch/volume
                                                        │
                        ┌───────────────────────────────┘
                        ▼
                 EdgeTtsClient（java.net.http.WebSocket）
                   wss://speech.platform.bing.com/.../readaloud/edge/v1
                   Sec-MS-GEC 握手令牌 + speech.config + ssml
                        │  mp3 分片
                        ▼
                 Mp3Decoder（JLayer）──▶ 16 位 PCM ──▶ WavFile
                        │
                        ▼
                 config/bbs/assets/audio/bbsvoice/<签名>.wav
```

### 三个必须记住的逆向结论（都是实测，不是猜的）

**① 握手令牌 `Sec-MS-GEC`**：没有它，websocket 升级直接 `403`。它是
「当前 Windows file time（100ns 刻度）向下取整到 5 分钟边界」+ 公开的 trusted client token 的
**大写 SHA-256**。有一个坑：刻度值约 1.3e17，超出 double 的 2^53 精度，所以**必须照着参考实现用
double 算、并用 double 的十进制输出**——"修正"成精确整数运算反而会让令牌和服务端不一致。
5 分钟取整是为了容忍时钟偏差。单测用参考实现的黄金值钉住了这一点（`SecMsGecTest`）。

**② 只接受 mp3 / webm-opus**：probe 过 6 种 outputFormat，`riff-24khz-16bit-mono-pcm`、
`raw-*-pcm`、`ogg-*-opus` 全部被 `1007 Unsupported Edge output format` 关闭连接。

**③ 一份 SSML 最多 2 个 `<prosody>` 元素**（这条最反直觉，也没在任何文档里）：

| SSML 形状 | 结果 |
| --- | --- |
| 1 个 `<prosody>` | ✅ |
| 2 个 `<prosody>`（属性不同、小数位不同都行） | ✅ |
| 3 / 4 / 5 / 6 个 `<prosody>` | ❌ `1007 SSML is invalid` |
| 嵌套 `<prosody>`、`<break>`、空 `<prosody>` 也算一个 | ❌ |

注意即使每个元素属性完全一样、文本只有一个字，第 3 个也照样被拒——所以这是**元素个数**的硬限制。
因此 `ProsodyPlanner` 把 ≥3 个分句合并成最多 2 组连续分组（按字数均衡），
`SsmlBuilder` 再多一道防御：超过 2 个直接抛 `IllegalArgumentException`，而不是把一个注定被拒的
文档发出去换回一个看不懂的 websocket 关闭码。

### 韵律是怎么标定的（`tools/EdgeTtsProbe.java`）

不需要启动游戏就能跑通**和 mod 完全相同**的渲染路径（`EdgeTtsBackend`）：

```bash
javac -encoding UTF-8 -d build/probe -cp "libs/jlayer-1.0.1.4.jar" src/main/java/com/bbsvoice/tts/**/*.java tools/EdgeTtsProbe.java
java -Dstdout.encoding=UTF-8 -cp "build/probe;libs/jlayer-1.0.1.4.jar" EdgeTtsProbe "你好，世界！" build/probe
```

不加参数就是**生产形态**（走 ProsodyPlanner 的多分句计划），`--single` 只发一个 span，`--matrix` 逐个属性扫一遍：

| 用例 | SSML 属性 | 时长 | 峰值 | RMS |
| --- | --- | --- | --- | --- |
| baseline | `rate=1 pitch=+0% vol=+0%` | 5.064s | 21785 | -20.9 dB |
| rate 1.5 | `rate=1.5` | 3.408s | 21851 | -21.0 dB |
| rate 0.7 | `rate=0.7` | 7.224s | 21866 | -21.0 dB |
| pitch +20% | `pitch=+20%` | 5.064s | 22561 | -21.0 dB |
| volume +80% | `vol=+80%` | 5.064s | 30830 | -17.4 dB |
| volume -60% | `vol=-60%` | 5.064s | 8508 | -28.9 dB |

读法：`rate` 只改时长，`volume` 只改电平，`pitch` 两者都不动（只动基频，这个工具不测）——
三条属性各自独立生效，写法正确。`volume` 必须用**相对**写法（`+80%`）：绝对写法上限就是 `100%`，
而 `100%` 恰好等于"不变"，没法表达"更响"。

`--dump <file.mp3>` 会把服务发回的 mp3 **原样落盘**（不解码）。单测用的
`src/test/resources/edge/hello.mp3` 就是这么采下来的：**解码器要对着服务真实发回的字节做回归**，
而不是对着自己造的一个测试文件——服务换了容器这件事，只有这样才跑得出来。

## 8. 构建

```bash
# 需要 JDK 17+（本项目用 JDK 21 构建，产物目标是 Java 17）
# 用仓库自带的 wrapper，版本已经锁定（Gradle 9.6.1）；Loom 1.15.5 要求 Gradle ≥ 9.2，
# 用 PATH 上的 Gradle 8.x 会在解析插件时就失败（Could not resolve net.fabricmc:fabric-loom）
.\gradlew.bat build    # 产物： build/libs/bbsvoice-1.0.0-1.20.4.jar（含内嵌的 JLayer）
.\gradlew.bat test     # 66 项纯 Java 单元测试（不需要游戏、不需要联网）
```

`gradle build` 会在 `test` 之后触发 `remapJar`；产物里已经包含 JLayer 的 81 个类文件
（`javazoom/jl/...`），没有遗留的签名文件，也没有被删掉的旧引擎类——这几点可以用
`jar tf build/libs/bbsvoice-1.0.0-1.20.4.jar` 直接核对。

编译需要一个**不在本仓库里**的本地 jar：`libs/bbs-2.3-1.20.4.jar`。

BBS 是第三方分支、Modrinth 上没有对应坐标，而且这个文件是 **BBS 作者的成品**（版权归作者，
本仓库不分发），所以克隆之后要自己准备一次——从你正在玩的整合包里把它拷进 `libs/`，
文件名按 `gradle.properties` 里的 `bbs_version=2.3` 命名：

```powershell
copy '<路径>' 'libs\bbs-2.3-1.20.4.jar'
```

在目标整合包里跑一次真机自检（开发用）：

```powershell
powershell -File tools/RunSelfTest.ps1 -ModJar '<路径>'
# 装进 versions/BBS/mods，带 -Dbbsvoice.selftest=1 启动，自检完写 bbsvoice-selftest.txt 并自动退出
```

自检覆盖 30 项：剪辑工厂注册、数据序列化往返、**老存档（旧引擎人物 id）回退**、语言文件、内置资源包、
缓存签名（文本/人物/韵律进签名，音量/语速/偏移不进）、**音调确实到达引擎**、曲线采样与开关往返、
录音分支的无文件保护、编辑器面板构造、**联网合成 + wav 非静音校验 + 语音时长上报 + 剪辑自动贴合
（新剪辑会长到语音长度 / 手动拖过的不动 / 开了自动适配的不动）**、OpenAL 加载与播放。
